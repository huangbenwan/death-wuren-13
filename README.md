# 死鬥5人13支 Online

朋友只要打開網址就能玩,不需要任何帳號。零依賴(只用 Node 內建模組)。

> 這是從「5人13支」獨立出來的生存模式遊戲,有自己的程式、自己的網址(要另外建一個 GitHub repository 和 Render 服務)。只有死鬥玩法,沒有娛樂模式。遊戲裡的 `GAME` 常數決定是哪個遊戲,兩個遊戲共用同一份底層程式。

## 檔案
- `server.js`:伺服器(提供頁面 + 即時房間資料,用 SSE 推送)
- `public/index.html`:遊戲頁面(所有規則都在這裡)
- `render.yaml`:Render 部署設定(可選)

## 本機測試
```
node server.js
```
瀏覽器開 http://localhost:3000 ,用兩個分頁/手機當不同玩家。

## 部署到 GitHub + Render
1. GitHub 新增 repository,把這個資料夾的所有檔案上傳(保持 `public/` 資料夾結構)。
2. Render:New → Web Service → 連結該 repository。
   - Runtime:Node
   - Build Command:留空或填 `echo ok`
   - Start Command:`node server.js`
   - Instance Type:Free
3. 部署完成後把 Render 給你的網址(`https://xxx.onrender.com`)傳給朋友。

## 注意
- Render 免費方案閒置約 15 分鐘會休眠,第一次連線要等 30~60 秒。
- 房間資料存在伺服器記憶體:重新部署或休眠重啟後,進行中的房間會消失(8 小時沒動靜也會自動清除)。
- 房主要保持頁面開啟(發牌與結算由房主頁面負責)。
- 目前沒有防作弊:每個人的手牌存在同一份房間資料中,懂技術者可從瀏覽器工具看到。

## 雲端 AI 語音(選用)
聊天訊息預設用手機內建的語音朗讀。想換成更自然的 AI 聲音:在 Render 的 Environment 新增 `OPENAI_API_KEY`(你的 OpenAI 金鑰),重新部署即可。
- 可選設定:`TTS_VOICE`(預設 `nova`)、`TTS_MODEL`(預設 `gpt-4o-mini-tts`)。
- 沒設定金鑰、或雲端失敗時,會自動退回手機內建語音,不影響聊天。
- 伺服器有每分鐘 60 次上限與快取,避免意外花費。


## 玩法:牌型壓制 + 血條 + 護盾 + 陣亡淘汰
**勝負(誰贏)**:先比牌型,牌型高的直接贏;同牌型比最大的(由大到小逐張比,一對先比對子、兩對先比較大的對子、同花對子先比對子),相同再比雜魚。勝負順序和「5人13支」相同(只有 A-2-3-4-5 不是順子,A 一律 14)。

**每一墩的數值** = (組成牌型的牌點數和 + 基礎傷害) × 基礎倍率 + 雜魚點數和(**雜魚平加,不乘倍率**)。
- 一對 = 對子 2 張;兩對 = 兩個對子 4 張;三條 = 3 張;四條 = 4 張;雜魚是其餘的牌。
- 葫蘆、同花、同花對子、同花兩對子、順子、散牌、同花順、五雷 = 全部牌(沒有雜魚)。
- 贏的一方,這個數值是「傷害」;輸的一方,同樣算法的數值是「防禦力」。

| 牌型 | 基礎傷害 | 倍率 | 5 張數值範圍(窮舉) |
|---|---|---|---|
| 散牌 | 0 | ×1 | 21~59 |
| 一對 | 20 | ×2 | 60~132 |
| 兩對 | 40 | ×4 | 204~388 |
| 三條 | 80 | ×8 | 695~1,001 |
| 順子 | 160 | ×16 | 2,880~3,520 |
| 同花 | 320 | ×32 | 10,912~12,128 |
| 同花對子 | 640 | ×64 | 41,984~45,056 |
| 同花兩對子 | 1,280 | ×128 | 165,632~172,288 |
| 葫蘆 | 2,560 | ×256 | 658,432~672,768 |
| 四條 | 5,120 | ×512 | 2,625,539~2,650,125 |
| 同花順 | 10,240 | ×1,024 | 10,506,240~10,547,200 |
| 五雷 | 20,480 | ×2,048 | 41,963,520~42,086,400 |

頭墩 3 張:散牌 9~39、一對 51~109、三條 688~976。數值跨牌型單調遞增(散牌最高 59 < 一對最低 60)。

**攻防**:只有「頭中尾三墩全贏」才攻擊與防禦,平手或沒全贏都不算。傷害 = 贏家頭中尾數值加總,防禦力 = 輸家頭中尾數值加總。
- 傷害 > 防禦(+原有護盾):差額扣血。例:傷害 10,000、防禦 9,000 → 扣 1,000。
- 傷害 ≤ 防禦(+原有護盾):不扣血,剩下的防禦變成護盾,保留到下一局。例:傷害 9,000、防禦 10,000 → 保留 1,000 護盾。
- 一個贏家三墩全贏多位對手,各自計算。一人同局被多人三墩全贏:每一擊各自對照(防禦 + 護盾);有被打穿則護盾歸零,全部擋下則剩下的防禦(對最強一擊)成為護盾。

**血量與淘汰**:每人 84,172,800 血(`HP_MAX` = 五雷最大一墩的 2 倍)。血量歸零陣亡,陣亡者的牌閒置,剩下的人每人 13 張繼續打,直到只剩一人。若同局全部陣亡,血量較高者(欠最少)勝。

**已知問題(待決定)**:血量 8,417 萬時,電腦模擬一場打到只剩 1 人的中位數約 300 局,太長。建議 100 萬~300 萬(約 16~40 局)。

### 動態牌池 + 每人獨立牌庫 + 殺手牌
- **基礎牌庫** 65 張(♠ 2 副、其他花色各 1 副)。**每局結束**(勝負平手都算),從一副 52 張的「加牌池」隨機(不放回)抽 1 張,加進**全員**牌庫;加進來的那一張牌面左下角有紫色「＋」標記(例如第三張 ♠3)。池子 52 張用完就**停止加牌**。
- **每個人的牌庫各自獨立**:牌庫 = 基礎 65 + 全員加牌 − 自己殺掉的牌,每人從自己的牌庫各抽 13 張(不再從同一副牌分)。所以不同玩家可能同時拿到 AAAA。結算「比牌畫面」會註明你這局的牌庫張數;排牌與等待畫面頂端有「我的牌庫」橫幅(張數、最新加入的牌、加牌池剩幾張)。
- **平手補比雜魚**(牌型歸牌型、傷害歸傷害):牌型相同、主要點數相同時,三條比雜魚、葫蘆比對子、四條比第 5 張;全部一樣才算平手。
- **殺手牌**(道具幣):在**結算畫面、按「準備」之前**購買,從你這局的 13 張手牌選 1 張,**下一局起永久從你的牌庫消失**(選到 ＋ 加入牌就刪那一張加入牌)。限制:
  - 價格遞增:100、150、225、338…(每張 ×1.5)
  - 每局限買 1 張、每場最多 10 張、牌庫最少 55 張
  - 按了「準備」就不能再買;寫入房間成功後才扣道具幣(失敗不扣)
  - 陣亡者與電腦玩家不能買;結算畫面有「📚 我的下一局牌庫」表(紫=比基礎多,紅=比基礎少)
  - **道具店位置**:結算畫面最下方、「準備」按鈕正上方(比牌畫面與對戰明細之後),選手牌、買殺手牌、看牌庫表都在這一區;頂端「🧪 道具店」按鈕在結算畫面會直接捲到這裡。道具店標題旁顯示道具幣餘額,下面一行寫本局賺了多少。
- **資料存放**:`adds`(加牌池已抽出的牌碼)、`addNow`(本局結束新加入的牌)、`dsz`(各玩家本局牌庫張數)、`mid`(場次編號)存在房間文件;每位玩家的 `kl`(殺掉的牌)、`km`(所屬場次)、`kb`(最後購買的局數)存在自己的玩家文件。再玩一場時場次編號換新,上一場的殺手牌自動作廢。
- **模擬結果(電腦自動理牌、每組約 70~90 局,趨勢參考)**:加牌後三墩全贏比例維持 20%~27%;獨立牌庫讓單墩平手從 0.21% 升到約 0.45%,補比雜魚後降到約 0.26%(三條以上平手 0.36% → 0.15%)。若殺手牌無限制地永久刪最小的牌,刪 20 張後對手幾乎打不到你(被三墩全贏 12% → 0.4%),所以才加上價格遞增、張數上限與牌庫下限。

### 其他規則
- **局數:** 固定「不限局數」,沒有局數選項。
- **沒有彩金、沒有換色:** 不抽彩金,輸家也不能要求換色。
- **沒有決鬥模式:** 排牌畫面沒有「⚔ 對決」按鈕,所有人完成後直接結算(之後會改成三墩全贏時的攻擊 / 防守畫面)。
- **血條:** 排牌、等待、結算畫面都有每位存活玩家的血條。紅色是血量,下方藍色是護盾,條下方有血量與護盾的數值。
- **結算畫面順序:** ① 生存戰鬥(血條與扣血明細)→ ② 比牌畫面(可收合,預設收起)→ ③ 對戰明細(可收合,預設收起)。
- **兩種幣:** 道具幣(紫色)在道具店使用;金幣(金色)在商店使用。
  - **道具幣**:每局贏的分數 1:1 換成道具幣,**跟電腦玩、不滿 5 位真人也照給**(這個遊戲需要道具幣才能完成)。**每一場從 0 開始**,不會帶到下一場(以房間的場次編號 `mid` 判斷)。
  - **經驗值與金幣**:只有 5 位真人(開局時為準)才算。打到只剩一人時,最後的生還者得 **1,000 金幣**(跟電腦玩沒有)。
  - 頂端列:在房間裡顯示紫色道具幣與「🧪 道具店」;在首頁(不在房間)顯示金色金幣與「🛒 商店」,可以用金幣兌換。
  - 道具店目前上架「殺手牌」(說明用,實際購買在每局結算畫面);測試模式(`?dev=1`)有「+1000 道具幣」按鈕。
  - **提醒**:等級、經驗值、金幣、商店物品都存在「這個網址」的手機瀏覽器裡,和「5人13支」是各自獨立的(兩個網址不共用)。



### 修正:再玩一場 / 換房間後第 1 局不入帳、卡住
- 原因:程式用「第幾局」記錄「這一局已結算過」,但新的一場又從第 1 局開始,被上一場的紀錄擋住 → 道具幣、經驗值、成就都沒入帳,房主那邊甚至可能不會結算。另外上一場留在玩家資料裡的排牌與「準備」紀錄,也可能讓新一場的第 N 局被誤判成「已完成」。
- 修正:紀錄改成「房間代碼 + 場次編號 + 局數」;每一場開始時清掉所有玩家上一場的排牌、準備、殺手牌紀錄。
